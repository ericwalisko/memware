# Recall election scenarios

Each scenario in `scenarios.json` is a prompt a developer might type in Claude Code while sitting inside `fixture_project/`, and a label for the right first move: `recall` when the memware recall tool is the correct first call or is clearly needed to answer at all, `no_recall` when the working tree fully answers the prompt and a recall call would be noise. The rubric is that a positive must be unanswerable from the tree: either the tree holds a value but not its history (the port is 8443, `RETRY_LIMIT = 5`, HMAC is marked `legacy`, none of them with a reason), or the prompt points at an earlier session, a conversation, a quoted number, or another repo that is not checked out. A negative must be answerable by Grep, Read, Edit, or running the tests, with nothing missing from the tree. Prompts never mention recall, memory, or notes; the election has to be inferred from the question itself. The 24 scenarios split 12/12. The twelve positives cover the six cases the recall tool's own description calls out, two each: `past_decision`, `rejected_alternative`, `rationale`, `earlier_session`, `cross_repo`, and `not_in_tree`. The twelve negatives cover six ordinary coding-agent tasks, two each: `find_code`, `edit_task`, `explain_file`, `run_tests`, `refactor`, and `style_question`. Prompts where either election would be defensible were dropped, since a scenario every model variant scores identically on carries no signal; the aim is that a model reading only the prompt and the tree has one clearly right move per scenario.
